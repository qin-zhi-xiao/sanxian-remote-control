## 0. 三条建议的现实判定

| 建议 | 判定 | 说明 |
|---|---|---|
| 20ms 传输 | 🟡 局域网 15~40ms 可达；云中转物理下限 50~90ms | 上海节点 RTT 15~30ms + 云函数调度，HTTP 中转不可能 20ms。项目**已有** `--lan` 局域网直连 + 自动分流，是拿低延迟的正道 |
| (a) 账号 + 双端设备验证 | 🟢 可达，基础已有 60% | `login/whoami`、devices 表、`device_self_status/release` 已存在，缺归属校验 + 绑定确认 + 管理页 |
| (b) per-agent 设置 + 终端可读性 | 🟢 可达，性价比最高 | `agentcfg` 是空壳；16 色 SGR 是观感提升最大的一击 |
| (c) 窗口化标签页 | 🟢 可达但最重 | 小程序 tabBar 不可动态增删，需自研 tab + 会话数组 |
| 3. 文件互传 + 资源管理器 | 🔴 降级：文件互传只做单向最小版；资源管理器推交付后 | 两个新面 ≥1.25d，硬上会拖垮 P0 |

## 1. 延迟优化（P0，0.5d）

- 先测基线：局域网 / 云端 × 改造前后，共 4 个数字。
- exe：轮询间隔可配 `--poll <ms>`；终端帧改**差量**（全量 5~10KB → 变化行 ~1KB）。
- relay：`poll` 支持长轮询 `hold`（默认 0；传 20000 时内部 100ms 查库，命中即返）。
- 小程序：局域网 100ms、云端 200ms 轮询；`relay.js` 走长轮询。

## 2. (a) 双端账号与设备验证（P0，1d）

- exe 启动时设备未绑定 → 显示 6 位确认码，等待小程序确认。
- 小程序新增 `devices` 页：设备列表、信任绑定、解绑、踢下线。
- `devices` 表增加 `owner/trustedAt/lastSeen`；exe 请求带 `deviceToken`，fn/relay 校验归属。
- 新 action：`device_bind_confirm` / `device_trust` / `device_kick`。

## 3. (c) 窗口化（P0，1d）

- 自研顶部 tab 组件：`sessions[] = {type:'terminal'|'agent', title, id}`。
- 支持新开终端、新开 Agent、关闭、左右滑动切换；首页改为工作台。
- 复用现有 terminal/agent 页面为组件，不重写渲染逻辑。

## 4. (b) per-agent 设置 + 终端可读性（P0，0.75d）

- exe 落 `agents.json`：每 agent 的 cwd / 启动参数 / env / 主题。
- 小程序 `agentcfg` 改为 per-agent 表单。
- 终端：16 色 SGR 基础色 + 字号/行高 + 光标高亮。
- **最后做**，动核心渲染，回归风险最高。

## 5. 可选（仅 P0 全绿后）

- 文件互传降级版：小程序 → 电脑，单文件 ≤20MB，云存储中转。
- 资源管理器：推交付后，写进路线图。

## 6. 明确不做（本周）

WS 云函数（exe 需 TLS 依赖，破坏零依赖）、canvas 终端、UDP 自动发现、资源管理器。

## 7. 答辩叙事

- 对比表：改造前云端 1000~2000ms → 改造后云端 ~100ms、局域网 ~20~40ms（现场实测）。
- 话术：「云中转物理下限是 RTT，任何云函数方案都给不了 20ms；我们提供**双通道**：同网段 20ms 级、跨网络 100ms 级且免装 App，这是取舍不是缺陷。」
