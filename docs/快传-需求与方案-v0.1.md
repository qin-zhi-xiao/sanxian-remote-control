## 一、主人的原始需求（对话原文要点）

> 「我想做的程序项目，是一个可以在手机上快捷打开电脑端的 Agent 和终端，甚至是部分电脑端应用软件的工具。这些都是在已经运行并且连接在手机上的电脑终端运行的。
> 项目的目的，就是更方便让人在离电脑比较远，或者不方便掏出电脑的情况下对电脑进行操作。
> 虽然网易 UU 远程原本就在做这个，但是它存在以下问题：1. 要钱；2. 需要下载；3. 私有化程度不够高。」

拆成四条硬指标：

| # | 需求 | 说明 |
|---|---|---|
| R1 | 手机上打开电脑的 **终端** | 发命令、看输出 |
| R2 | 手机上打开电脑的 **Agent** | 指电脑上已经跑着的 AI Agent（如本地 Agent 程序） |
| R3 | 手机上打开 **部分电脑端应用软件** | 唤起/操作某些桌面 App |
| R4 | 三个痛点对齐 | 不花钱、不用装 App（小程序即用）、私有化程度高（自己的数据自己的机器） |

用户自己的后续判断（对话里提出的两个方向）：
- 「教学项目是否为学生提供在线服务器？不行的话可以试试公网穿透」
- 「官方提供了云函数和云托管……云托管可以直接把 relay 打成容器镜像传上去」

## 三、方案

### 3.1 架构选择

三条候选路（对话里 AI 小老师给过 A/B/C），结论维持 **A：云数据库当消息总线（relay）**，理由：

- 不花一分钱（云开发在教育平台免费）
- 不需要公网 IP、不需要买域名、不需要备案
- 电脑端只是个本地小脚本，不装任何客户端 → 对上 R4「不用下载」「私有化」
- 延迟 1～3 秒，对「发一条命令、等一条结果」完全够用

B（公网穿透 + 备案域名）对中学生项目来说基本做不完；C（纯演示版）只能当过渡。

### 3.2 数据流

```
  手机（小程序）                云数据库（免费）                  电脑（本地脚本）
  ┌──────────┐                 ┌──────────────┐                ┌──────────────┐
  │ 输入命令  │ ──写入──────▶   │ commands     │ ◀──每 1.5s 轮询─│ pending/      │
  │          │                 │  status:     │                │ (按 deviceCode)│
  │ 看结果    │ ◀──监听/轮询──  │  pending     │ ──回写─────────▶│ 执行 → stdout │
  └──────────┘                 │  running     │                │  exitCode     │
                               │  done/error  │                └──────────────┘
                               └──────────────┘
```

关键点：**电脑端是主动出站轮询**，永远不需要被外部连进来。这是「不备案、不穿透」能成立的根本原因。

### 3.3 数据模型（字段约定）

集合 `devices`
| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 自动 |
| `deviceCode` | string | 6 位配对码，展示在电脑脚本命令行里，手机上输入它完成配对 |
| `deviceName` | string | 如「书房台式机」 |
| `secret` | string | 32 位随机串，电脑脚本持有；回写结果时校验，防止别人冒充 |
| `lastSeen` | number | 电脑脚本每次轮询更新，用来算在线/离线 |
| `status` | string | `online` / `offline` |

集合 `commands`
| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 自动 |
| `deviceCode` | string | 目标设备 |
| `kind` | string | `shell` / `app` / `agent` |
| `payload` | string | shell=命令行；app=应用标识；agent=发给 Agent 的对话内容 |
| `cwd` | string | 工作目录（可选） |
| `status` | string | `pending` → `running` → `done` / `error` / `timeout` |
| `createdAt` / `startedAt` / `finishedAt` | number | 毫秒时间戳 |
| `stdout` / `stderr` | string | 输出（截断到 8KB，避免超限） |
| `exitCode` | number | 退出码 |

集合 `pairs`（如平台权限模型允许客户端读他人数据，才有必要）

### 3.4 页面结构

```
pages/
  index/      控制台：设备卡 + 发送框 + 最近结果（首页）
  terminal/   终端：命令历史 + 输出滚动区
  agent/      和电脑端 Agent 对话（复用 commands，kind=agent）
  apps/       应用宫格：点击 → 写一条 kind=app 的命令
  pair/       配对：输入 6 位配对码 + 设备命名
```

全站 `app.json` 的 `navigationBarTitleText` 现在是默认的 `"WeChat"`，要改成「快传」。

### 3.5 安全（这个项目最大的坑，必须写进第一版）

「手机发一条字符串，电脑直接执行」= 远程代码执行。教育版小程序虽然搜不到，但同校同平台的人可能拿到入口。最低限度：

1. **配对码 + secret 双因素**：配对码只是一次性的入场券，回写结果必须带 secret
2. **命令白名单/黑名单**：默认只放行白名单（如 `ls`、`git status`、自定义脚本名），危险模式（`rm -rf`、`shutdown`、`curl | sh`）直接拒
3. **超时**：`running` 超过 60s 由脚本标 `timeout` 并杀进程
4. **每次只跑一条**：队列串行，不做并发（也避免把免费额度烧掉）
5. 小程序端不保存 secret，只保存 `deviceCode` + 本地昵称

## 四、与主人已经讨论到的进度

AI 小老师问了 3 个问题，前两个主人已经回答（提供了需求 + 提出穿透/云托管思路），**第 3 个问题主人还没选**：

> 问题 3/3：电脑端那个轮询脚本，你希望我怎么处理？
> A. 我在项目里给你写一份完整的电脑端脚本（Node.js），你复制到电脑上跑
> B. 只做小程序端，电脑端脚本我自己写，你告诉我接口和字段约定
> C. 先只做小程序端 + 一个「模拟电脑」的调试开关，方便你在手机上先看效果

我的建议：**C → A**。先用模拟开关把 UI 和交互跑通（手机上立刻能看到效果，比赛/展示时也不怕电脑没开），再补真脚本。

## 五、动手前必须先验证的三件事

这三件没验完就写代码，可能全白写。

1. **电脑端脚本能不能拿到云开发凭据？**
   - 需要环境 ID + 能调数据库的密钥（云开发 HTTP API 要 access_token，或小程序端 SDK 的等价方式）。
   - 教育版后台是否给 `AppSecret` / 云开发环境 ID？**未验证。**
   - 拿不到 → 退路：小程序 ↔ 电脑同局域网直连（教育版已去掉服务器域名限制，理论上可不备案，但小程序 `wx.request` 是否允许 `http://` 局域网 IP **需实测**）。

2. **云函数/云托管到底有没有？**
   - AI 小老师说没有；官方介绍里没提。去编辑器文件树看有没有新建云函数的入口、后台看有没有云托管菜单。
   - 有 → 可以走主人想的「云托管 relay 容器」，延迟和实时性都更好。

3. **数据库权限模型**
   - 教育版云数据库的默认读写权限是「仅创建者可读写」还是可配置？电脑脚本以什么身份写数据？
   - 这条决定 3.3 的字段和权限策略要不要加中继集合。
