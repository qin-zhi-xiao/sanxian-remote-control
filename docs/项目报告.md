## 一、项目是什么

在手机上打开电脑端的终端，直接使用电脑上的智能体（Claude Code、Codex、Hermes、DeepSeek Harness），
并且在智能体卡住时有一个可用的终端兜底。

**要解决的问题**（来自最初的需求原话）：

> 可以在手机上快捷打开电脑端的 Agent 和终端，甚至是部分电脑端应用软件的工具。
> 网易 UU 远程原本就在做这个，但：1. 要钱；2. 需要下载；3. 私有化程度不够高。

**我们的答案**：一个微信小程序 + 一个单文件 exe，不装 App、不付订阅费、数据全在自己的云环境里。

## 三、已实现的功能

### 3.1 电脑端（kuaichuan.exe）

| 功能 | 说明 |
|---|---|
| ConPTY 伪终端 | 真正的 Windows 伪终端，TUI 程序能正常运行 |
| 三种 shell | Git Bash / CMD / PowerShell，手机端可随时切换 |
| 终端画面网格 | 程序端维护 120×40 字符网格，支持清屏、光标定位、备用屏 |
| 智能体探测 | 自动发现并读取版本，覆盖 PATH、`LOCALAPPDATA\Programs`、npm 全局等目录 |
| 心跳与设备注册 | 向云端登记设备名、配对码、智能体列表 |
| 危险命令拦截 | 内置黑名单，防止误操作 |
| 凭据外置 | 从同目录 `.cloudbase-apikey` 读密钥，不写死在代码里 |

### 3.2 小程序端（`app.json` 注册 7 个页面）

| 页面 | 功能 |
|---|---|
| `index` | 连接配置页 + 欢迎页：自动列出在线电脑、手动输入配对码、真实连通测试 |
| `login` | 登录页（2026-11 新增，账号体系） |
| `account` | 账号页（2026-11 新增） |

| `agentcfg` | 智能体配置页（2026-11 新增） |

> 报告初版只写了 4 个页面；登录 / 账号 / 智能体配置是后续迭代加入的。

## 五、开发过程中解决的关键问题

这一节记录踩过的坑，都是真问题，不是推测。

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| 1 | 云函数部署"成功"但行为不变 | `term_*` 代码插在了 `return unknown action` 之后，是死代码 | 移到兜底 return 之前 |
| 2 | 小程序整片黑屏 | `relay.js` 的 `module.exports` 引用了未定义的函数，`require` 直接抛错 | 补上函数定义 |
| 3 | 终端内容重复刷屏 | `term_drain` 把多帧整屏快照**拼接**后推送 | 只推最新一帧 |
| 4 | 换行后内容粘在上一行 | `newline()` 只换行不归零列号 | `cur_c = 0` |
| 5 | `Bad file descriptor` | ConPTY 的管道两端主进程没关，孙进程继承了坏句柄 | `CloseHandle(in_r/out_w)` |
| 6 | 启动 claude 就退回 bash | 首次 shell 轮询误判为"用户切换"，把正在启动的程序杀了 | 首次只记录不重置 |
| 7 | 屏幕上冒出孤立的 `4`、`m` | CSI 解析器不认中间字节（空格），序列被拆散 | 按标准规则重写：参数 0x20–0x3F，终止 0x40–0x7E |
| 8 | TUI 退出后主屏残留 | 没实现备用屏 | 支持 `?1049` / `?1047` / `?47` |

**方法论教训**：第 7 个问题，我靠猜改了 7 次都没修好；
最后把 ConPTY 的原始字节流 dump 出来，一眼就看出 bash 根本没发 `\r` 重绘。
**先测量再动手**，比反复猜测有效得多。

## 六、当前限制（诚实说明）

| 限制 | 原因 | 影响 |
|---|---|---|
| **延迟 1～2 秒** | 走云数据库轮询（600ms 间隔 + 云函数往返） | 打字有明显延迟感 |
| **无法实时推送** | `db.watch()` 需要 `wx-server-sdk`，但云函数运行时没有这个包 | 只能轮询 |
| **Ctrl+C 无效** | 往 ConPTY 输入管道写 0x03 不产生中断信号 | TUI 卡住只能退回重开 |
| 无颜色 | 自写 VT 网格只存字符，不存 SGR 属性 | 全单色 |

其中 **实时推送**这条做过完整验证：

```
sdk_test => {"info":{"hasSdk":false,
  "err":"require 失败: Cannot find module 'wx-server-sdk'"}}
```

云函数用 HTTP API + 服务密钥写入的是另一套租户库，小程序客户端看不到（`watch` 恒定收到 0 条）。
要把 SDK 打进包里，但它体积大、之前试过 19MB 包直接失败。

| 级别 | 问题 |

| P1 | 版本号五处不一致；文档数字（4 页面 / 2000 行 / 348 KB）集体过时 |

### 10.2 已修复并上线

1. 两处内联 Key → `process.env.KC_API_KEY`；会话密钥 → `process.env.KC_SESS_SECRET`（缺失即快速失败）。
2. `.gitignore` 改成白名单，只放行 `releases/` 里的正式分发文件。
3. relay 增加 `Authorization: Bearer` 定长比较校验；匿名 / 错密钥返回 401，
   服务端未配置返回 503；新增免鉴权 `GET /health` 供平台探活。
4. 云端按「先建新 Key → 注入环境变量 → 同步本机三处 `.cloudbase-apikey` → 部署两个函数
   → 全部验证通过 → 最后吊销旧 Key」执行，全程无链路空窗。

**线上验证**：匿名 `401`；带新 Key `ping` `200` + `dbOk:true`；`/health` `200`；
`kuaichuan-fn` 的 `ping` `dbOk:true`、`whoami` 假 token 返回「登录已过期」。全部通过。
旧 Key 已失效，公开仓库历史里那串成了废纸。
